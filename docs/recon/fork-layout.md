## 2. MLA attention paths — two disjoint stacks

**Generic MLA (V3-style absorbed, what GLM should use):** `tpu_inference/layers/vllm/custom_ops/mla_attention.py` — `VllmMultiHeadLatentAttentionWrapper` registered via `@MultiHeadLatentAttentionWrapper.register_oot` (`mla_attention.py:206-207`), so any upstream vLLM model built on `MLAModules`/`MultiHeadLatentAttentionWrapper` (deepseek_v2.py family) is intercepted automatically. It supports `q_lora_rank` split of `fused_qkv_a_proj` (`mla_attention.py:282-296`), and **carries the DSA indexer**: `self.indexer`/`is_sparse`/`topk_tokens` (`mla_attention.py:244-252`), **but the indexer output is computed and discarded** — `_topk_indices = self.indexer(...)` at `mla_attention.py:318-320` is never passed to attention; the backend impl (`tpu_inference/layers/vllm/backends/flash_attn_mla.py:50-165`) takes no topk/sparse args and does absorbed MQA: q_nope·W_UK_T einsum (`flash_attn_mla.py:151-158`) → `mla_attention()` (`tpu_inference/layers/common/attention_interface.py:485,546-584`) → Pallas kernel `mla_ragged_paged_attention` (`tpu_inference/kernels/mla/v2/kernel.py:2171`), latent cache kv_c+k_pe, tuned for the 512+64 split, `r_dim % 128 == 0` required (per `deepseek_v4_attention.py:49-51`). **Sparse top-k is NOT implemented in the v2 kernel — DSA on TPU currently degrades to dense.**

**DSV4-specific (NOT reusable for GLM):** `tpu_inference/layers/vllm/custom_ops/deepseek_v4_attention.py` — header (lines 36-52) documents why DSV4 cannot use mla.v2: full-latent K==V (no W_UV), per-head sink, inverse-RoPE on output. Class `VllmDeepseekV4MLAAttention` (`deepseek_v4_attention.py:1197`), dense/compressed MQA in raw JAX (`dsv4_dense_mqa` :420, `dsv4_paged_dense_mqa` :622, `dsv4_paged_compressed_mqa` :698, CSA indexer bias :967). Pallas decode kernel `dsv4_paged_decode` (`tpu_inference/kernels/mla/dsv4/kernel.py:299`), gated `DSV4_PALLAS_DECODE` (`deepseek_v4_attention.py:1841,2006`; kernel header dsv4/kernel.py:38).
