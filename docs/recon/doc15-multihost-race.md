# docs/15-worker3-multihost-race-blocker.md — summary

## 1. Serving-time recompile race: root cause

- Under a hybrid mesh (`model>1`, head-TP × token-DP), per-step attention/logits/sampling/prompt-logprobs programs contain **cross-host collectives**; each is a **launch group** — all 8 hosts must enqueue the same program with the same launch id in lockstep (docs/15:124-129).
- Some serving programs compile **live at serving** instead of at warmup. Live compiles finish **staggered across hosts (~21 s measured spread)**; the slow host arrives at the collective with a stale launch id → the group cannot rendezvous → the 32-chip step **halts** (docs/15:135-139, 163-166). The libtpu error is XLA-**compiler timing** (`impure_hlo_parallel_compile`), not a wall-clock deadline — no timeout knob helps (docs/15:141-145, ruled out at docs/15:189).
- One host, **worker-3 = 192.168.0.11**, consistently loses across all runs/code versions/jit modules; gcloud reports `HEALTHY` because the check doesn't measure compile speed (docs/15:151-156, 115-119).
- Doc 15's original framing ("data-shaped shapes can't be bucket-precompiled", docs/15:135-139) was later **corrected**: the real class is a **dummy-precompile-vs-real-serving XLA layout mismatch** — the lowering is cached but the HLO→executable **backend compile misses** because the dummy input's XLA-chosen layout ≠ the real forward output's layout. `ForbidCompile`/`VLLM_XLA_CHECK_RECOMPILATION` is **blind** to this: it hooks the *lowering* cache (`pxla._cached_lowering_to_hlo`), so the sub-cube showed "0 recompiles" while the pod still halted (`tpu_inference/runner/utils.py:303-312`). Also: the precompile of the prompt-logprobs all-gather was gated `if hybrid_mesh:` (compilation_manager.py:1207 then) so pure-DP had exactly **one racer** too (docs/15:12-16).

## 2. ExecutableCompileObserver (the detector)

- **File:** `tpu_inference/runner/utils.py:300-419` (`class ExecutableCompileObserver`); commit `86139d88`; CPU test `tests/runner/test_executable_compile_observer.py`.
- Hooks the backend-compile chokepoint `jax._src.compiler.backend_compile_and_load` (+ defensively `_compile_and_share_module`), recording every **genuine (HLO, layout) executable compile** by `jit_<name>` (utils.py:314-321, 384-404). In-memory executable-cache hits never reach it.
- **Gate:** `DSV4_OBSERVE_COMPILES=1` (log histogram per serving half-step) or `=trace` (also capture user-frame tracebacks) — wired in `tpu_inference/runner/tpu_runner.py:492-500, 1006-1023`; off → byte-identical (nothing patched, utils.py:334-335).
- **Single-host reproduction:** a layout mismatch live-compiles on one host too (just with no launch group to lose), so **a COLD compilation cache on the 4-chip sub-cube makes the race class deterministically observable** — count serving-region backend compiles to 0 (utils.py:323-325). `raise_on_compile=True` = the warmup-invariant guard: turns a probabilistic pod hang into a loud deterministic warmup error (utils.py:327-332).

## 3. Drive-real-layout fix pattern (detector-validated 9→5→2→1→0 serving compiles)

- **`a6534d33`** — during the backbone (`enforce_eager=False`) precompile, **stash the REAL forward hidden output `out[1]` keyed by num_tokens** (`compilation_manager.py:103, 505-511`) and feed it — not a dummy — to `_precompile_gather_logprobs` (:1153, :1297), so compute_logits/select/fp32-cast precompile on serving's actual XLA output layout. Kills the `jit_compute_logits_func`/`jit__select_from_array_fn`/`jit_convert_element_type` racers.
- **`3d3762ee`** — precompile `DeviceBuffer.unpack_arrays`' **`jnp.split`** on the per-step host-input blob (`_precompile_input_unpack`; the pre-forward `jit_split` racer) + precompile the prompt-logprobs reshard on `copy_to_host_async`'d fields.
- **`1b55a3e9`** — eliminate the host-reshard race **by construction**: fold the prompt-logprobs all-gather **inside** the bucket-precompiled gather via `jax.lax.with_sharding_constraint(…, P())` on the three small outputs (`layers/jax/sample/sampling.py:170-196`), so no separate `jit__lambda` reshard exists to race. Pod result: cold head-TP 5-shot, HALT=0, **0 serving backend compiles**.

## 4. GLM bring-up (hybrid model>1 mesh): redo/watch list

- **Enumerate before pod:** cold-cache sub-cube run with `DSV4_OBSERVE_COMPILES=trace`; drive serving-region backend compiles to **0**. Do not trust `VLLM_XLA_CHECK_RECOMPILATION` (blind to layout misses).
- **Backbone precompile must survive the real forward:** DSV4's dummy-metadata precompile crashed on the CSA `n_win==0` concat (fixed `bebbc769`, docs/15:186-187). GLM's **DSA indexer (top-k 2048), IndexShare, and MTP layer** are the analogous degenerate-dummy hazards — fix so `enforce_eager=False` runs, since real-layout capture depends on it.
- **Re-wire the real-hidden capture** for GLM's forward output convention (`out[1]` non-donated assumption, compilation_manager.py:505-511) and verify `_precompile_gather_logprobs` covers **both** mesh shapes — the pure-DP-vs-hybrid gating bug (docs/15:12-16) is the trap; precompile select/sample/gather for the actual serving `num_reqs`/bucket set (docs/15:33-35).
- **Watch new collectives:** head-axis psum on o-proj, EXPERT_DATA↔ATTN_DATA reshards, sample/prompt-logprobs gathers (docs/15:168-171) — GLM's 64 MLA heads/257-expert routing changes shapes but not the class. Keep the folded all-gather (`sampling.py`) — model-independent, verify present on the new branch.
- **Validation bar:** pod passes are probabilistic — 3/3 `--limit 200` runs (CLAUDE.md quality bar); forensic on any halt: `grep "different launch id"` (host IP) + last `impure_hlo_parallel_compile is DISABLED. jit_<name>` line (docs/15:254-255).
