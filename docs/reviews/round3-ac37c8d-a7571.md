2. LOW-MEDIUM (correctness, documented guard overstated) — bench/extract.py:113 and test_bench.py:60. The thousands-comma regex `(?<=\d),(?=\d{3}(\D|$))` misreads any tuple/interval/set whose next element is exactly 3 digits: `norm_math("(1,200)")` → `"(1200)"`, `norm_math("0,001")` vs gold `"1"` → scores True, `"3,141"` (European decimal) → `"3141"`. The test comment "`(1,2)` tuples untouched — kept" holds only for non-3-digit components. Impact on the shipped benchmarks is near-nil (AIME gold ∈ [0,999] so a stripped pair is ≥4 digits and can't collide; GSM8K gold is a comma-stripped scalar and questions don't ask for pairs), but norm_math is generic and this is a latent false-POSITIVE (score inflation) vector, e.g. GSM8K gold "1200" vs model interval "(1,200)".
