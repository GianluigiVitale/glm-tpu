# Fused feature reductions and BF16 prefill (2026-09-19)

Opt-in work outside frozen `MODEL_SOURCE=edecdd94`; trained-weight admission
and DB610 token comparison remain open.

## Fused decode input reductions

`Ws32PerfOptions(fused_feature_reductions=True, bf16_resident=True)` computes
Q-a, KV-a and (on full-indexer layers) WK/head partials separately, concatenates
the FP32 partials, and executes one feature-4 `psum`. Splitting happens before
the original BF16 Q/KV rounding and normalization; WK/head stay FP32. No
contractions or weights are concatenated. Shared-indexer layers fuse two sums;
full-indexer layers fuse four. Default remains off until timing review.

CPU32 proof covers full/shared indexers, M1/M3 rows, unequal feature shards and
unaligned projection widths. All sums and downstream Q/KV normalization are
bitwise equal. The isolated JAX graph contains one `psum`. An eight-layer,
three-step comparison also gives bitwise equal state, caches, selected scores,
residual and tokens against the same D1/D8/D5/D10 program without fusion.
The eight decode/projection tests passed in 359.76 s. These CPU observations
do not assert universal bitwise behavior under TPU collective scheduling.

## D8 prefill composition

`build_ws32_prefill_challenger_program(..., bf16_resident=True,
lse_attention=True)` accepts the same `Bf16DecoderWeights` as decode. Attention,
DSA, dense and shared-expert FP8 tables are decoded once. Routed expert tables
and grouped/panel kernels stay FP8. Completed M64 repaired-key production uses
the original materialized WK inputs; finite checks, causal writes and all-owner
atomic admission remain in the frozen composition.

Private function bindings replace projection dependencies. A private weight
adapter aliases BF16 tables into the frozen named fields only inside this
composition; it passes `None` for the removed scales. The BF16 matmul helpers
reject raw bits or scale arguments. No frozen module globals are modified.

The canonical dense window still performs four 32-row placements in physical
B128. A private window mirror differs only in moving its canonical dense
import to module scope for dependency binding; an AST test proves the rest of
the function unchanged. B114/B128 dense tests check masked outputs, health and
routing metadata. The complete canonical B128/expert-panel CPU fixture passed
in 80.41 s, including refusal after completion.

D8 changes MXU accumulation order, a numerical boundary even with identical
BF16 operands. Two short complete-prefill comparisons (P1 off/on) passed in
116.06 s: discrete state and token equality, floating state within the fixture
bound `rtol=.02, atol=.0625`, and unchanged committed caches on refused append.
This bound is a fixture assertion, not a universal model error guarantee.
CPU's batched DotThunk rejects BF16×BF16→FP32; `linear_interpret=True` widens
already-rounded BF16 operands exactly to FP32, as the Pallas interpreter does.
Production uses BF16 operands and FP32 accumulation.

## Full-model measurement path

`tools/perf_tpu_microbench.py --which prefill_model --prompt-length 2048`
compiles and runs all 78 layers with canonical B128 dense placement and admitted
paired/sorted settings (key tile512). It materializes each repair WK through
two separately completed original decode/promote executables. An all-host
memory vote accounts for resident allocator bytes plus executable output,
temporary and code bytes, with 512 MiB reserve, before dispatch. Receipts record
HLO hashes, memory analysis/counters, per-block times, full-prompt wall time,
health and final token. One warm first block is excluded; timed prefill starts
from a fresh empty prefix. Synthetic routing and token trails are not trained
model throughput or quality evidence.

Release checks passed: 524 passed, 1 skipped; source pin and package unchanged.
