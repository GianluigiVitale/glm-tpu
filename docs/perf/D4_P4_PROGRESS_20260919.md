# D4 host boundaries, long prefill and P4 panels (2026-09-19)

Research outside `MODEL_SOURCE=edecdd94`; no serving default is replaced.

## D4 compact request loop

`glm_tpu/perf/request_loop.py` wraps the existing challenger in an outer JIT.
A request's original SHA256/24-bit FP32 uniforms are placed once, including
index0 for prefill. Each decode selects `state.position - prompt_length + 1`.
The wrapper returns the original model result plus an int32 vector containing
token, all-owner health, next position and context length. Out-of-range draw
indices and nonfinite/out-of-range uniforms make compact health false.

`PackedRequestSession` retains the original prefill, stop, pause/resume and
release behavior. Decode reads the compact vector once, combines timing and
state admission into one fleet vote, commits the state/token before delivery,
and performs the existing delivery-success vote. It performs two votes per
decode token instead of three and no per-token uniform `device_put`. A failed
or ambiguous delivery still poisons the session and cannot emit a retry. The
callback must be the corresponding packed program with the same request's bank
and prompt length bound; arbitrary metadata is not an independent state proof.

Sixteen CPU tests passed in 55.40 s. They cover complete CPU32 model-output
bitwise equality, correct RNG index progression, invalid index/NaN refusal,
all-owner health propagation, local/remote refusal, clock failures, delivery
failure after commit, EOS/length stopping, pause/resume and boundary-call
counts. CPU proof does not replace TPU composition or timing evidence.

The queued TPU comparison uses the same sampled D1/D8/D5/D10 model, synthetic
weights and deterministic draws in both loops. Both perform real eight-host
votes and append events to an in-memory sink. Timing excludes compilation and
five warm steps; it includes all per-token host boundaries. Token trails, final
state/residual bit patterns and actual votes/transfers are compared. This is
not a network or filesystem delivery-latency measurement.

## Complete synthetic 128K acquisition

The existing compact pending-cache commit path (`pending_cache_rows`,
`flat_pending_rows`, `capture_barrier`) is enabled for the 131,072-token prompt,
capacity131,584. The complete canonical B128/expert-panel CPU comparison with
these flags passed in81.90 s, including atomic refusal. The benchmark releases
unused raw non-routed weights after completed WK preparation and, for a single
variant, drops the initial empty cache reference before timed iteration so it
does not retain a third full-context state. Model arithmetic is unchanged.

The run has passed all-rank memory admission and completed its first16,384
tokens. It remains in progress; no complete throughput is claimed yet.

## P4 wider output panels

`wide_prefill_panel_fp8_matmul` mirrors the frozen routed panel kernel with
N256/N512 output tiles. M32 panel packing and increasing K128 reduction order
are unchanged; every N128 stripe has its own FP32 accumulator and scale row.
The default prefill builder still uses the frozen N256 kernel.

Six CPU cases passed in8.34 s, covering FP32/BF16 outputs, empty owners and
skewed panels, with bitwise equality at N256 and N512. The queued TPU experiment
includes packing/unpacking at real gate `[32,2048,1536]` and down
`[32,1536,2048]` local weight geometry, with balanced and concentrated routes.
Each output exposes both owner axes so feature-partial values are never
incorrectly declared replicas. No speedup is claimed before that experiment.
